PC Technician

AI that diagnoses and repairs a Linux system one step at a time — and a USB profiler that works out an unknown device's protocol and writes you a driver.

🔬 Profiles unknown USB hardware 🐧 Generates a Linux driver 🩺 Diagnoses before it touches anything 🌐 Repairs machines over Tailscale 🥧 Cross-compiles for Raspberry Pi

AI-guided repair

A fixed protocol — diagnose before touching, verify at every step

🩺

Diagnose first, touch later

The AI works through a set order — hardware, kernel, drivers, network, storage — running one check at a time and reading the result before deciding the next move. It doesn't skip steps or make assumptions.

🔧

Least-dangerous fix first

Reload a module or restart a service before anything riskier. Snapshot the config before a change that could bite. Confirm it worked after every step.

⏱️

Survives a reboot

Any fix that needs a restart sets a resume script first, so the AI picks up exactly where it left off when the machine comes back.

🌐

Fix machines you're not sitting at

Diagnose and repair anything on your Tailscale network. The AI runs commands on the remote machine, reads the results and carries on — across reboots included.

USB Driver Porter

Plug in an unknown device → capture how it talks → get a Linux driver

🔬

30-second profile

Plug the device in and run a short capture. The profiler records how it actually communicates — that profile drives everything that follows. Then it picks one of three routes, based on how custom the device turns out to be:

Standard

Known device class

Keyboards, serial adapters, storage and other standard types. You get udev rules and a modprobe config — nothing to compile.

Part-custom

Some vendor-specific protocol

You get a small userspace program or an audio plugin that speaks the device's protocol. Still runs in user space — no kernel build.

Proprietary

Fully custom protocol

You get a complete kernel module, DKMS-packaged so it survives kernel updates, and cross-compiled for Raspberry Pi 3, 4 and 5.
