TrXi-Ctrl

Linuxデスクトップ向けの無料リモートコントロール — Bluetooth、ファイアウォール、オーディオ、メディア、ウィンドウ、ターミナル、画面共有、共有クリップボード、AIチャットを、スマートフォンまたは別のコンピューターから操作 — さらに、root化したスマートフォンでは、VPNホットスポットとUSBマスストレージ。Debian Trixie向けに構築。他のほとんどのX11 Linuxデスクトップでも動作します。

デスクトップアプリ

TrXi-Ctrlはスマートフォンに加え、Windows、macOS、Linuxでも動作するようになりました。ノートパソコンからLinuxマシンを操作：同じ画面を、本物のマウスとキーボードで。

🖱️

マウスとキーボードのリモートデスクトップ

マウスでリモート画面を移動、クリック（左、中、右）、ドラッグ、スクロールできます。ご自身のキーボードで入力し、Ctrl+Cなどのショートカットも使用できます。スマートフォンのタッチ操作は変わりません。

🔇

映像と一緒に音声

リモートデスクトップは画面と一緒にPCの音声を再生します。デスクトップタブにミュートボタンがあります。

🖼️

画像またはコードでペアリング

PCのそばにいませんか？そこにいる人がペアリングQRをメールで送れます — アプリのスキャナー（画像アイコン）で画像を開いてください。カメラのないコンピューターは代わりにペアリングコードを入力します。

🛡️

デバイスとホワイトリスト

ゲートウェイの管理ページには、接続したすべてのデバイスとそのオンライン状態が一覧表示され、チェックを入れたデバイスのみを許可できます — Tailscale 名、または自宅ネットワークでは MAC アドレスで指定します。

🎛️

ゲートウェイマネージャー

ゲートウェイサービスを開始、停止、再起動し、ペアリング QR を表示、保存、コピーし、ゲートウェイのログを読むための小さなデスクトップパネル。

リモートデスクトップ

WebRTC による全画面共有。PC の音声付き — ネットワーク上のどこからでもデスクトップを表示して操作できます。スマートフォンでは、タッチでマウスを操作し、画面上のバーでテキストを送信します。Windows、macOS、Linux アプリでは、自分のマウスとキーボードが直接機能します。クリックやキー入力はほぼ即座にデスクトップに表示されます。感じる遅延は、戻ってくる画面更新によるもので、入力によるものではありません。

📋

共有クリップボード

PCがハブです。すべてのデバイスがクリップボードの内容をそこへ送信し、PC自身のクリップボードに直接入ってすぐに貼り付けられます。クリップボード画面には直近50件の共有履歴が表示されます。選んだデバイスやグループにアイテムを送信したり、受信したくないデバイスをミュートしたり、アイテムをタップしてこのデバイスにコピーしたりできます。バックグラウンドでスマートフォンのクリップボードから読み書きされることはなく、タップしたときだけ行われます。

🔐

ホットスポットVPN

スマートフォンのTailscale出口ノードを、そのWi-Fiホットスポット上のすべてのデバイスと共有します — ノートPC、テレビ、ゲーム機は何もインストールせずにVPNを利用できます。ホットスポットまたはTailscaleが再起動するとルーティングは自動的に再適用され、起動スクリプトで再起動後にすべてを復元できます。ルーターとして接続したままにするスマートフォン向けに設計：充電制限、Tailscaleをバッテリー最適化から除外、常時接続VPN。

💾

USBマスストレージ

スマートフォンを任意のPCに接続するとUSBドライブとして表示されます。最大256 GBのディスクイメージを数秒で作成 — FAT32（すべてのOSが読み取り可能）、ext4（4 GBのファイル制限なし）、またはEFIパーティション付きの起動可能なGPTディスクでノートPCがスマートフォンから起動可能 — その後、読み書きまたは読み取り専用で共有するか、スマートフォン自体で開きます。スマートフォンのSDカードやUSBドライブをPCに渡すこともできます。共有中もADBは接続されたままです。

trixie-gateway — デスクトップ側、単一の自己完結型バイナリ

📦

単一バイナリ、Python不要

単一の自己完結型実行ファイルをダウンロード — マシンにPython、pip、venvは不要です。現在のバイナリ（v0.2.0-test2、2026年9月）は10月のセキュリティ修正より前のものです。新しいものが公開されるまでは、それらを適用するためにソースからゲートウェイを実行してください。aiohttp + aiortcで構築されており、Pythonから実行したい場合のためにソースは今もGitHubにあります。単体で、またはsystemdサービスとして動作し、Tailscale/LANアドレスで待ち受けます。

🔌

~110個のRESTエンドポイント

上記のすべてのスマートフォンアプリ機能に加え、OpenAI互換の /v1/chat/completions 設定した任意のAIプロバイダーにルーティングします。

🧩

MCPサーバー同梱

media_mcp_server.py メディア制御（ステータス、再生、一時停止、シーク、音量、開く、閲覧）をstdio JSON-RPC経由のMCPツールとして公開します — スマートフォンアプリが使用するのと同じセッションデータと制御パスなので、AIエージェントとスマートフォンは常に同じものを見ます。

Debian Trixie 向けに構築 — 他でどこで動作するかについて正直に

プラットフォームステータス理由
Debian トリクシー✓ ここで開発・テスト済み—
Fatdog64 / Puppy Linux ファミリー✓ 動作するはずLayers 機能はどちらの下でも union-fs ブランチを検出します /aufs （Fatdog64 派生、このマシンを含む）または /initrd （標準 Puppy）を自動的に — /initrd パスは実際の Puppy インストールに対してテストされておらず、実地検証ではなく文書化された慣例に基づいています
その他の X11 Linux デスクトップ✓ 動作するはずBlueZ、iptables、pactl互換のPulseAudio/PipeWire、およびX11セッションが必要です。Waylandは実験的です：以下のものを備えたコンポジタ ext-image-copy-capture およびforeign-toplevelプロトコル（mangoでテスト済み）。GNOMEおよびKDEのWaylandセッションはまだサポートされていません
Windows 11🧪 実験的なテストビルド画面共有、マウス/キーボード、ウィンドウ一覧、音量、ターミナルは Windows 向けに実装されています。バイナリは自動 CI でビルドおよび起動しますが、 実際の Windows マシンではまだ実行されていません — 粗削りな部分を想定してください。Bluetooth、ファイアウォール、レイヤー、明るさ、ネットワーク、Media Center は Linux 専用のままで、応答します 501
macOS (インテルおよび Apple シリコン)🧪 実験的なテストビルドWindows と同じ機能セットで、Quartz、AVFoundation、および osascriptを使用します。両方のアーキテクチャで CI でビルドおよび起動しますが、 実際の Mac では未テストです。アプリは署名されておらず、macOS は画面収録とアクセシビリティの許可を求めます

アプリをインストール

どのビルドもまだ Apple や Microsoft による署名がされていないため、各システムは信頼するかどうかを一度だけ尋ねます

🤖

アンドロイド

スマートフォンで APK をダウンロードして開きます。Android は初回にブラウザーまたはファイルマネージャーからのインストールを許可するよう求めます — 許可してから、インストールをタップします。過去 10 年間のほとんどのスマートフォンは arm64 APK を必要とします。armv7 は古い 32 ビットのスマートフォンでのみ使用してください。以降の更新はゲートウェイから直接届けることができます: 更新 タブ。

🍏

iPhoneとiPad

iOSビルドは署名されていないため、サイドロードします：インストール 横から または オルタナティブストア をコンピュータで、iPhoneを接続し、 .ipa をドロップして、任意のApple IDでサインインします。次にiPhoneで：設定 → 一般 → VPNとデバイス管理 → Apple IDを信頼します。無料のApple IDでは、アプリを7日ごとに再サイドロードする必要があります。

🪟

Windows 10 / 11

ダウンロードしたファイルを任意の場所に解凍し（例： C:\Programs\TrXi-Ctrl)、実行します trxi_ctrl.exe。初回はSmartScreenが「WindowsによってPCが保護されました」と表示します： 詳細情報 → 実行。ファイルは一緒に保管してください — .exeにはDLLと data フォルダが隣に必要です。

🍎

macOS

開いて .dmg ドラッグして TrXi-Ctrl に入れます アプリケーション。初回は、アプリを右クリック → 開ける → 開く（公証されていないためダブルクリックはブロックされます）。macOS がまだ拒否する場合は、システム設定 → プライバシーとセキュリティ → このまま開く.

🐧

Linux

GTK 3 と libmpv が必要です：Debian/Ubuntu では sudo apt install libgtk-3-0 libmpv2。次に tar -xzf TrXi-Ctrl-1.1.0-linux.tar.gz を実行します ./bundle/trxi_ctrl。フォルダは bundle まとめて保持してください。

🔗

デスクトップとペアリング

ゲートウェイを実行している Linux デスクトップで、開きます http://localhost:8772/admin （または Gateway Manager）。 スマートフォンとMac: アプリ → 設定 → QRスキャナーアイコン → QRをスキャンするか、画像アイコンをタップして誰かがメールで送ったQR画像を開きます。 WindowsとLinux: ゲートウェイアドレスとQRの下に表示されているペアリングコードを入力します。コードは1回のみ有効で、10分間持続します。両方のデバイスが同じTailscaleネットワークまたはLAN上にある必要があります。

ゲートウェイをインストール

制御したいDebian Trixie（または互換Linux）マシン上で

# Linux — スタンドアロンバイナリ、他にインストールするものはありません # (v0.2.0-test2 は10月のセキュリティ修正より前のものです。それらについては、ソースから実行してください — 下記参照) curl -LO https://github.com/cou645/trixie-gateway/releases/download/v0.2.0-test2/trixie-gateway-linux-x86_64.tar.gz tar -xzf trixie-gateway-linux-x86_64.tar.gz ./trixie-gateway --port 8772 # その後、スマホアプリで: 設定 → ゲートウェイURL → http://<this-machine's-tailscale-or-LAN-ip>:8772 # または、両方が同じTailscaleネットワーク上にいる場合は「Discover Peers」をタップしてください

Pythonの方がいい？ git clone https://github.com/cou645/trixie-gateway.git、次に pip install -r requirements.txt そして python3 gateway.py --port 8772。systemdサービスとしての実行を含む完全なインストールドキュメントは、リポジトリの README.md.

🧪 Windows & macOS テストビルド はこちら リリースページ (trixie-gateway-windows-x86_64.exe, trixie-gateway-macos-arm64.zip, trixie-gateway-macos-x86_64.zip)。これらは署名されていないため、Windows SmartScreen は「不明な発行元」と表示し（詳細情報 → 実行）、macOS は初回起動をブロックします（右クリック → 開く）。不具合があれば報告してください。
